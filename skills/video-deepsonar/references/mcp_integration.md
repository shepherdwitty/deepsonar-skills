# DeepSonar MCP 集成指南（原生 Tool Call 交互归因版）

> **核心设计准则：原生 Tool Call 优先！**
> 
> 完成 MCP 安装并重启 Session 后，DeepSonar 的 4 个工具直接驻留在 Agent 的工具树中。
> 归因与核验必须在 Agent 的**思考链中以原生 Tool Call 的方式交互式推进**，像调用本地函数一样自然推理。
> **禁止退化为编写临时 Python 脚本或后台子进程硬搓！**

---

## 一、原生工具定义与语义（4 大核心风控工具 + 2 大免费运维工具）

| 原生工具名 | 核心定位 | 最佳调用时机 |
| :--- | :--- | :--- |
| `list_platforms` | 开工闸门与分类字典 | 开工前确认平台开放状态（douyin 为 true），并获取二级分类名（作为 search_rules 过滤项） |
| `diagnose_risk` | 违规归因主力诊断 | 将口播全文、包装印制文字、核心高危宣称送入诊断，获取风险判定与引用规则线索 |
| `search_rules` | 语义/标题双通道检索 | 针对存疑话术、极限词边界或特定法规（如输入《化妆品监督管理条例》）定向检索细则 |
| `get_rule_detail` | 调阅规则全文（**孤证不立**） | 每一条进报告的违规结论，**必须**调用此工具调阅规则清洗后 Markdown 全文，核验依据并提取官方原文链接 |
| `get_usage` 🆓 | API Key 用量与有效期自查 | 随时查询当前 Key 的剩余次数、已用额度及有效期；免费工具不扣减配额，配额耗尽亦可调用 |
| `get_data_version` 🆓 | 规则库数据新鲜度自查 | 查询平台规则库的数据更新时间与更新节奏（滞后时附提示）；用于确认规则时效性；免费工具不扣配额 |

## 二、归因与核验黄金流程（交互式推理）

在 Agent 的思考链路中按以下 4 步展开：

### 1. 闸门检查
```json
// Agent 直接发起原生调用：
call: list_platforms({})
```
确认返回中 `douyin.open == true`。

### 2. 多维度分批诊断（diagnose_risk）
不要把所有无关信息揉成一坨。采用结构化分批策略（通常 3~6 次调用，严格控制在 10 次以内）：
- **调用 A（口播全文）**：`diagnose_risk({ content: full_transcript_text, platform: "douyin" })`
- **调用 B（商品名称与包装对比）**：将「口播宣传品名」与「拉片中锁定的包装备案实名」做对比送入，排查私改品名、超范围功效宣称风险。
- **调用 C（资质证据核实）**：若口播宣称检测报告、专利、权威认证，送入核实是否存在缺乏凭据承诺。
- **调用 D（高危极限词/功效表述）**：提取文案中的绝对化用词（如“从根源”“全网最”），单独送入确保精准命中。

### 3. 孤证不立：调阅全文核验（get_rule_detail）
**这是风控报告严谨性的生命线！**
对 `diagnose_risk` 返回的每一条引用（`cited_sources`）：
```json
// Agent 直接发起原生调用：
call: get_rule_detail({ rule_id: source.rule_id })
```
- **验证通过（`verified: true`）**：调阅全文确认条款明确支持判定，从全文摘录最具法律/规则效力的惩罚条款，并将 `meta.url` 透传为官方原文链接；
- **存疑或缺失（`verified: false`）**：若全文未明确禁止、规则已下架（`is_delisted=true`）或未提供有效 URL，降级为疑似条目，提醒人工复核。

### 4. 补充定向检索（search_rules）
对存疑的特定类目规范（如美妆行业宣传细则、价格标示规范），调用：
```json
call: search_rules({ query: "化妆品宣称消痘祛痘规范", platform: "douyin", limit: 3 })
```

## 三、规则原文链接纪律（铁律）

报告中的每一个命中条款都必须成为商家自查和申诉的依据：
1. **链接唯一来源**：只能透传 `get_rule_detail` 的 `meta.url` 或 `diagnose_risk` 的 `cited_sources[].rule_url`；
2. **严禁臆造拼接**：绝对禁止通过规则名称自行拼接 URL（包括猜测 jinritemai 域名路径）；
3. **透传真实规则名称**：规则名必须完全沿用官方标题（带书名号及【】符号），不得缩写或漏字。

## 四、极限兜底通道（严禁擅自偷跑，仅限用户特许）

**超级第一原则红线**：配置自动写入后，必须强制暂停并要求用户重启会话以加载原生工具。
**仅当用户明确指示“不允许重启/无法重启，特许本次直接临时直调”时**，才被允许使用命令行脚本兜底：
```bash
python3 scripts/mcp_call.py diagnose_risk '{"content": "...", "platform": "douyin"}'
```
未经用户明确授权，Agent 绝对严禁直接调用 `mcp_call.py` 绕过原生重启流程！
